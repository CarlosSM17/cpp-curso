💡AnalogíaUn cruce de caminos con letrero

Vas en bicicleta y llegas a un cruce con un letrero: «Si llueve, toma el camino techado; si no, toma el parque». No recorres ambos caminos: evalúas la condición (¿llueve?) y eliges uno. 7Condiciones compuestas y cortocircuitoElementos aislados
A B A && B A \|\| B !A
true true true true false
true false false true false
false true false true true
false false false false true

Cortocircuito: en A && B, si A es falso, B ni se evalúa (el resultado ya es falso). En A || B, si A es verdadero, B no se evalúa. Por eso if (d != 0 && n / d > 2) es seguro: nunca divide entre cero.

Rangos: en matemáticas se escribe 0 < x < 10; en C++ debe escribirse 0 < x && x < 10.

De Morgan (Ruta B): !(A && B) equivale a !A || !B; !(A || B) equivale a !A && !B.

Protocolo verbal

Una experta resuelve un problema en voz alta: qué hace (cómo) y por qué lo hace.

🎙Protocolo verbalProtocolo verbal · Una experta programa los descuentos de una tiendaModalidad Ejemplo resuelto

Guion para narración segmentada (≈ 3–4 min), con el diagrama de flujo y el código en pantalla.

Problema: «Si la compra supera $1000 y el cliente es frecuente: 20 % de descuento. Si solo supera $1000: 10 %. Si es frecuente pero compra $1000 o menos: 5 %. En otro caso, sin descuento».

Segmento 1 — Tabla antes que código. Cómo Hago una tabla con las dos preguntas (¿> 1000? ¿frecuente?) y sus cuatro combinaciones, y escribo el descuento de cada una. Por qué Dos condiciones de sí/no producen exactamente cuatro casos; la tabla me garantiza que no olvido ninguno.

Segmento 2 — Orden de la escalera. Cómo Pongo primero el caso más restrictivo: monto > 1000 && frecuente. Luego monto > 1000, después frecuente y al final else. Por qué En una escalera gana la primera condición verdadera; si preguntara primero monto > 1000, un cliente frecuente con $1500 recibiría solo 10 %.

Segmento 3 — Leer el «sí/no». Cómo Leo la respuesta como char y la convierto en bool frecuente = (resp == 'S' || resp == 's');. Por qué Así la escalera queda legible y acepto mayúscula o minúscula.

Segmento 4 — Probar fronteras. Cómo Pruebo $1500 S, $1500 N, $1000 S (¡justo en el límite!) y $800 N. Por qué El valor 1000 decide si se usa > o >=; el enunciado dice «supera», así que 1000 no recibe el descuento por monto.

Tema04. Estructuras selectivas: if, if-else y decisiones anidadas
Duración sugerida4 h · 2 sesiones de 2 h
Conocimientos previosTema 03 (operadores relacionales y lógicos, expresiones).

1. Objetivos de aprendizaje por nivel

Ruta A: estudiantes sin conocimientos previos del tema · Ruta B: estudiantes con conocimientos previos (el diagnóstico de la Fase 1 decide la ruta; ver la guía docente).

Ruta A Al terminar podrás…Ruta B Al terminar podrás…
  • Escribir condiciones con operadores relacionales (< > <= >= == !=) y lógicos (&& || !).
  • Usar if, if-else y la escalera if-else if-else para elegir entre caminos.
  • Representar decisiones con diagramas de flujo y pseudocódigo (Si … Entonces … SiNo).
  • Validar datos de entrada y diseñar casos de prueba que recorran todos los caminos.
  • Diseñar decisiones anidadas y transformarlas en escaleras o condiciones compuestas equivalentes.
  • Usar el operador ternario ?: y el if con inicializador de C++17.
  • Explicar la evaluación en cortocircuito y aplicar las leyes de De Morgan.
  • Evitar errores clásicos: = vs ==, ; tras el if, else colgante, comparación de double.
